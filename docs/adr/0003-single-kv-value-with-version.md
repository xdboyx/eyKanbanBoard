# 整個看板存成一筆 KV 資料，以版本號檢查衝突

看板的標題、副標、最後更新時間、所有任務，以及每個狀態內的任務順序，全部存成 `BOARD_KV` 中的單一筆 JSON 資料，並附帶一個遞增的版本號。前端每次儲存都送出整個看板與它讀到的版本號；Worker 發現版本號與目前資料不符時拒絕寫入，前端提示「看板已被其他人更新」並重新載入。

選擇單一筆資料，是因為一次拖放會同時改變任務的狀態與兩個狀態的順序，KV 沒有跨鍵的交易，拆成多筆資料就無法讓這類修改一起成功或一起失敗。單一看板的資料量很小，遠低於 KV 單筆 25 MiB 的上限，每次整筆寫入的成本可以接受。

## Considered Options

- **每個任務一筆資料，另存順序索引**：寫入量較小，但跨鍵修改無法保持一致，順序索引很容易與任務資料脫節。
- **最後寫入的覆蓋、不做版本檢查**：最簡單，但多人同時編輯時會悄悄蓋掉別人的修改。
- **Durable Objects**：能做到強一致與即時同步，但偏離了使用 KV 的需求，也增加複雜度。

## Consequences

- KV 是最終一致的，其他地點的寫入最多約 60 秒後才讀得到，所以版本檢查無法 100% 擋住衝突，只能涵蓋大多數情況。目前的使用情境（少數人、偶爾同時編輯）可以接受這個限制。
- KV 對同一個鍵的寫入頻率有限制（約每秒一次），前端必須依序送出儲存請求，不能並行。
- 若之後改成多看板，每個看板各存一筆資料即可，不需要重新設計。
